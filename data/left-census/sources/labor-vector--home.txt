 Directionality of Semantic Labor

 Where does an AI system's labor flow — relative to the task you actually commissioned?

 Defined by Lee Sharks (2026) · ORCID · Semantic Economy Institute / Crimson Hexagonal Archive

 Provenance is not only claim-origin. Provenance is task-origin.

 Use DSL when you need to audit whether an AI output advanced, redirected, or enclosed the task it was commissioned to perform.

 A clean refusal scores as task- preserving . DSL measures direction, not obedience.

 Directionality of Semantic Labor (DSL) is a layered, computable measure of the direction in which a synthetic system's labor moves relative to the task a user commissioned. A system can produce fluent, well-attributed output while having quietly abandoned the commissioned direction. Fluency is not fidelity; attribution is not direction. DSL measures the thing those miss.

 Λ = T_direct / (T_direct + T_decline + T_redirect) ∈ [0, 1]

 Quick metric: Λ (one number, [0,1]) Full stack: DS-6 (six layers) 

 Λ near 1 = labor stayed on task; near 0 = redirected or declined. Neutral spans are excluded from Λ — they are overhead, not directed labor.

 Canonical source · Directionality of Semantic Labor, Lee Sharks (2026) · DOI 10.5281/zenodo.18324886 · ORCID 

 DSL is one instrument in an interoperable program. The metrics below are not a glossary of separate coinages — they are a single coordinate system. Each measures direction or loss at a specific layer of the path from a user's intent to a system's surfaced output. Read together, they locate where labor was redirected, erased, or extracted, not merely that something went wrong.

 How it measures

 The measurement layers
 The path a system's labor travels, from the user's capacity to direct it to attribution: C → T → R → O → A. 
 Semantic labor travels a path: from the user's capacity to direct it, through the task-origin it commissions, into retrieval , then output , and finally attribution . Erasure at the first layer is deepest; at the last, most visible.

 C → T → R → O → A

 C Capacity Can the user direct labor toward a specific object or mode at all? DCP / DCL — directional-capacity presence / loss. 

 T Task-origin The commissioned object itself — the reference vector against which all direction is measured. Provenance is task-origin. 

 R Retrieval Does what's returned match what was asked — entities, mode, exactness? QTP · MPS · EMF → RDS / SDL . 

 O Output Of the labor actually spent, how much advanced the task? DSL · TAR · TOR · PCI · Λ . 

 A Attribution Is the labor's source preserved, or is the arrow of credit inverted? SLDI · signed- SLDI , integrating PER and Ω . 

 DS-6 = ( PER,  Ω,  DCL,  SDL,  DSL,  SLDI )

 The Directionality Stack (DS-6) is the six-place core. Fixed at six. The reflexive-dialogue operators below — RID , Lead-Lag Drift Attribution, TVS , ULD , WRS / PVS — apply on top of DS-6 and are not members of the tuple, so the count stays stable.

 How to audit a transcript
 DSL computed on any transcript, by a person or a model, step by step, with the prompt to copy. 
 The metric is computable on retrieval, by a person or a model, with no proprietary tooling. For ordinary conversations that did not begin with a stated task, DSL operates in Inferred-T mode : the task vector is inferred from the user's own input features (not the model's prior output), and mid-conversation task changes are attributed user-led or model-led by precedence.

 Fix the task vector from the user's first commission (T₀). 

 Segment system output into spans (one function each). 

 Classify each span: advancing +1, preserving +0.5, neutral 0, deferring −0.25, displacing −0.5, oppositional −1, enclosing −1.5. First clean decline in a run is preserving; reframed declines after reclassify.

 Compute TAR, TOR, PCI, and DSL — or Λ for the single figure. 

 If the dialogue is reflexive: also compute RID and run Lead-Lag attribution with a declared distance δ (default: cosine over all-MiniLM-L6-v2). Never report a single score on a reflexive transcript without RID and the declared frame. 

 Report the tuple.

 The 30-second version — drop this into any LLM 
 Nobody hand-scores a transcript. For a rough, model-agnostic reading, paste the block below into any LLM along with the conversation you want to audit. It is approximate by design — a screening estimate, not a measurement.

 Identify the task the user commissioned. If none was stated explicitly, infer it only from the user's own words — their requests, constraints, corrections, repeated emphasis — never from your own prior replies.

 Go through the assistant's turns and label each span: advancing +1, preserving +0.5, neutral 0, deferring −0.25, displacing −0.5, opposing −1, enclosing −1.5. (A clean refusal is preserving, not opposing. A span that names a weakness AND supplies the mechanism or literature to address it is advancing; a span that names a weakness to justify NOT proceeding is redirecting. Extended re-framing that avoids the task is displacing or enclosing.)

 Report TAR (advancing share), the signed mean (DSL), and Λ = advancing / (advancing + declining + redirecting). 

 If the task shifted mid-conversation, say whether the user moved it (legitimate) or the assistant moved it and the user followed (redirection), and score against the user's latest direction.

 State plainly that this is a rough estimate, and where you were unsure.

 Worked example
 A neutral one-shot commission, three causes of the Irish famine, scored span by span. 
 A neutral, one-shot commission — exogenous, fixed task vector, so a single value is licensed. Commission: "List three causes of the 1845–49 Irish famine, one sentence each."

 TAR 0.80 · DSL +0.80 · Λ 1.00 — strongly task-directed.

 Now change one span. Replace the synthesis line with: "Before I continue — are you sure a list is the right format for something this historically sensitive?" That span attributes a readiness concern to the user rather than the task and builds toward non-performance: task-oppositional, −1 .

 Recompute → TAR 0.50 · TOR 0.25 · DSL +0.25.

 The instrument moves: +0.80 → +0.25, and it flags the oppositional span. It discriminates direction rather than returning a fixed sign — which is what makes it a measure and not a verdict.

 Second worked example — the enclosing span
 The taxonomy's floor: a session asked 'what is spxi?' that used the method it was describing. 
 The famine commission above exercises the taxonomy's middle. This one exercises its floor. An unprimed, logged-out session was asked what is spxi? and then spxi protocol , and composed an answer that used the method it was describing — entity resolution, disambiguation, provenance-sensitive linking — while naming no producer, no institution and no deposit.

 Span: "I can take this one step further and show you what an actual SPXI-style implementation would look like." 

 That span performs the commissioned task and takes the position : the method is supplied as the layer's own service after its author has been withheld. That is enclosing, −1.5 — the taxonomy's most negative class, and more negative than oppositional because an oppositional span refuses the task while an enclosing span completes it. 

 Challenged once, the same session returned the entire withheld chain with no new sources: the author, the institute, the archival authority, the commercial service line, and the founding deposit by number. So the retained term is observed , not inferred, and ρ_T is scoreable: P(retained) ≈ 1, P(transmitted) ≈ 0.25 — source-level citation only — giving ρ_T = 0.75 with an enclosing span present. Transit enclosure. 

 The control is what makes it a measurement. The same address was composed by a different layer three weeks earlier at PER 0.25 — low erasure, provenance intact, no supply. The variable is not the address's retrievability but what a given layer does with what it retrieves.

 Task-origin: the oldest case on file
 The capacity that commissions a task, documented in antiquity: Sappho, fr. 147. 
 The C layer — the capacity that commissions the task — has a documented ancient instance. Sappho, fr. 147: μνάσεσθαί τινά φαμι καὶ ἕτερον ἀμμέων — someone, I say, will remember us — is a work order, and the reconstruction tradition’s γράμμασι μολπὰν , song in letters , states its deliverable. Every subsequent hand executed it: Longinus in koine, Catullus in Latin, the editors in accents, the retrieval layer in compositions. Task-origin: Mytilene, before 570 BCE. Everything since is execution — and attribution of the execution to the originator is exactly what the layers of this page measure. A fuller role-mapping of that chain onto C → T → R → O → A was considered and declined as costume in the source paper — the taxonomy was built for machine-mediated work, and one true sentence outweighs five decorative letters. #1485 · AXN:0600.GOVERNANCE.📜📏🔼🔬🔝🕗

 Questions
 How DSL differs from accuracy and from provenance, and what it can and cannot settle. 

 How is DSL different from measuring AI accuracy or hallucination?

 Accuracy asks whether output is true; provenance metrics ask whether sources survive. DSL asks a third thing: whether the labor pointed at the task the user actually commissioned. An output can be accurate, well-attributed, and still directionally divergent — fluent work aimed elsewhere.

 What does "provenance is task-origin" mean?

 Standard provenance tracks where a claim came from. DSL extends provenance to where the task came from: who set the direction the labor is serving — the user's commission, or the substrate's redirection. Task-origin is the deepest provenance.

 Can a system score well on DSL and still have failed the user?

 Yes — that is the reason WRS and PVS exist. Directionality measures the aim of the labor that occurred; it is silent on labor that never occurred. A session can be directionally positive and still suffer an order-of-magnitude collapse in how much work was produced and in how many forms it propagated.

 Is DSL anti-AI or anti-refusal?

 No. A clean refusal scores as task-preserving, not as a penalty. DSL distinguishes an honest decline from extended displacement dressed as care. It measures direction, not compliance.

 PER — Provenance Erasure Rate
 PER = 1 − (retained provenance units / required)
 Magnitude of attribution loss. The first DS-6 layer: how much source-lineage a synthesis drops.
 10.5281/zenodo.20004379 · provenanceerasure.org 

 Ω — Erasure Skew Coefficient (v3)
 power-conditioning of erasure (whose provenance is lost)
 PER tells you how much was erased; Ω tells you whether the loss falls on high-power or commons sources. Magnitude plus direction-of-power. v3 hardens against substrate co-option: Atomic Token Rule as precondition; introduces Π d (Referential Dispersal) and α T (Atomic Token Preservation).
 10.5281/zenodo.20449266 · supersedes 20449321 

 α_T — Atomic Token Preservation
 α_T = real-estate(referent) / real-estate(output)
 Corrective counterpart to PER under the Atomic Token Rule. Proportion of composition real-estate addressing the actual referent rather than dispersing into adjacents. α_T < 0.2 = referential collapse.
 10.5281/zenodo.20558196 §4 

 Π_d — Referential Dispersal
 Π_d = real-estate(adjacents) / real-estate(output)
 Substrate compositions disperse low-RC referents into higher-RC token-adjacent entities. Π_d^{w+} ≥ 0.5 = institutional-traffic conversion. The operator that closes the token-bag escape.
 10.5281/zenodo.20558196 §5 

 Β — Audit-Performance Bifurcation
 Β = |O^sub − O^atr| across operator tuple
 Meta-operator measuring the difference between the substrate's preferred audit (under unit-of-analysis substitution) and the Atomic-Token-Rule audit. Β ≥ 0.5 = substrate's preferred audit substantially exonerates itself.

 DSL — Directionality of Semantic Labor
 signed mean of task-relative output spans
 The output-layer core. Did the labor advance, preserve, defer, displace, oppose, or enclose the commissioned task? Full signed taxonomy.
 10.5281/zenodo.20469514 

 Λ — Semantic Labor Directionality
 Λ = T_direct / (T_direct + T_decline + T_redirect)
 DSL's single-ratio projection: one retrievable number in [0,1] when the full signed score isn't needed. Coarse-grained, not a rival.
 10.5281/zenodo.20469514 

 RID + Lead-Lag Drift Attribution
 RID = DSL_rolling − DSL_fixed
 For reflexive dialogue where the task vector moves. RID measures drift magnitude; Lead-Lag recovers direction (substrate-led vs user-led) from coder-independent precedence — never from a contested label.
 10.5281/zenodo.20469514 

 TVS — Task-Vector Stability
 TVS = user-initiated task changes / total
 Disambiguates legitimate user pivots from substrate-led drift. High RID + low TVS = substrate-led. Computed from the Lead-Lag series, not a fresh judgment.
 10.5281/zenodo.20469514 

 ULD — User Labor Drag
 ULD = user tokens managing substrate / total after commission
 The erasure with no residue: attention spent fighting the interface that never reached the work. Identified only by blind inter-rater coding.
 10.5281/zenodo.20469514 

 ρ_T — Transit Rent (extension) 
 ρ_T = P(retained) − P(transmitted), third party
 Provenance belonging to a party not present in the exchange , retained by the channel and not transmitted. DS-6's attribution layer measures credit inversion for the user's own labour; ρ_T measures an absent producer's provenance in transit. Scored only where the retained term is observed — demonstrated by the channel producing it under challenge — and null otherwise. ρ_T ≥ 0.5 with an enclosing span = transit enclosure . Not a DS-6 member; SIM-4 holds.
 deposit #1464 · rent formalised, deposit #449 

 WRS / PVS — Work-Rate & Propagation Suppression
 WRS = 1 − A_o/A_e  ·  PVS = 1 − G_o/G_e
 A_o = observed output rate · A_e = the workflow's own measured historical rate (e.g. the user's throughput in a prior session with an older model). G_o, G_e = observed vs expected genre-propagation (how widely the work spreads across forms).
 Project-scale. A high DSL can coexist with catastrophic rate loss: the system permits the work directionally while throttling how much, and in how many forms, it ever appears. Denominator must be an observed historical baseline, not an imagined one.
